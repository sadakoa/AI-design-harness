AI Design Harness

github.com/sadakoa/AI-design-harness

A small starter kit for teams where people and AI agents design UI together. It is a repo of plain files plus three skills and a check script.

WHY

Why it exists

Design knowledge lives in designers' heads. This writes it down where agents can use it too.

Today

❌ One long doc mixes rules, values and one-off decisions

❌ Agents read all of it, every time

❌ Review findings stay buried in comments

With the harness

✅ One question, one file

✅ Agents read only what the task needs

✅ Findings flow back into the rules

AI Design Harness

3

Build turns a PRD into a one-page proposal. Review checks it one lens at a time. Anything that might matter beyond that screen goes into the feedback log. Once a week, promote-feedback sorts the log, and a person decides what becomes a rule. The design system sits in the middle, and the next build reads from it.

AI Design Harness

7

Every finding starts open in work/feedback.md. Once a week promote-feedback groups them and suggests where each should go, but a person decides. Adopted changes go in a PR with a row in decisions.md. Local ones stay with that screen. Dropped ones keep their row and the reason.

IN PRACTICE

What the check catches

npm run check runs on your machine and on every pull request.

Index drift

A file not in INDEX.md, or a mismatched question

Stale tokens

tokens.css not rebuilt after tokens.json changed

Hard-coded colors

Raw colors in screens and options (R-01)

Unknown variables

CSS variables that aren't in tokens.css

Duplicate IDs

Two P-, R-, D- or FB- entries with one number

Loose ends

Adopted feedback with no decision behind it

AI Design Harness

9

If a machine can catch it, the machine should. The check has no dependencies. Lines you tag with a feedback ID are skipped on purpose, so breaking a rule is allowed as long as it is recorded.

IN PRACTICE

Running it as a team

First months

Only maintainers change the design system. Decide in batches.

Then

Designers open PRs too. Start with copy and guidelines.

Every week

Someone runs promote-feedback. A person decides.

Approvals

With two or more people, require a Code Owner's review.

NOT FOR

Screens with no precedent. Keep designers on the moments that change the experience.

AI Design Harness

10

Start small: maintainers only, decide in batches. Open it up once the output is steady. GitHub won't let you approve your own PR, so with one person, let a PR sit a day and reread the diff. Agents can draft options for brand-new screens, but they won't reach a shippable bar on their own.
